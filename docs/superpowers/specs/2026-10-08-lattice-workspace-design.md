## Workspace and brand

Use white **LATTICE**, all caps, Bricolage Grotesque 600 at 20px with 0.015em tracking. Preserve the supplied SVG geometry, masks, and minus-45-degree rotation in a 30px square; keep a 4px element gap, vertically centered. Bundle the font and its license so the installed extension works without third-party font requests. Other interface typography remains the existing product font.

The menu labels are File, Edit, Graph, Node, Preview, Workflows, Tools, Help. They have no idle button boxes or shadows; hover, active menus, and keyboard focus remain visible. Keep root Run/Stop, phase/activation state, autosave and effective request bounds visible. Workflow setup and role defaults belong in a dedicated panel, rather than the selected-node inspector. Personal material moves to an explicit Library drawer; its legacy editing and save-by-drag capabilities remain reachable.

Use `var(--SmartThemeQuoteColor, #e18a24)` as the interaction accent. Family/artifact colors and failure red retain their meanings. Shared rounded corners are 4px for windows, nodes and popups, 2px for compact controls and shelf rows. The graph window has a recessed frame with visible inner dark edges and a restrained lower/outer lip. The active tab joins the graph's outer outline with a smooth rounded shoulder; it has no bottom stroke or second enclosing rectangle. Theme changes cannot override this workspace geometry accidentally. Execution/selection rings compose without changing dimensions.

One preview pane sits above the graph and one details pane on the right. A handle between preview and graph redistributes their height; dragging and keyboard arrows resize it. Collapse/reopen preserves the preview source and previous height. No preview-size slider. Pane resizing preserves graph-local positions, selection, camera, recordings and a running workflow. Supported widths are 1,024, 736, 360 and 320px, with accessible overflow controls and intentional narrow layouts.

## Shelf and discovery

The graph surface covers the full pane beneath a floating shelf. The shelf is a sibling of the renderer-owned host, outside its camera transform. There is no reserved left column or persistent exclusion zone; nodes may be dragged underneath the shelf and use the space below it. Initial/default insertion may choose a visible unoccupied position, but explicit drag/drop coordinates remain exact.

Family order: Input, Shaping, Surface, Transpose, Derive, Output, Subgraphs. Current native assignments are Scene Context/Reply Snapshot → Input; Smart Compactor/Response Plan → Shaping; Repair → Surface; Pattern Scan/Validate Patches → Derive; Guidance/Review Gate/Apply Reply → Output. Transpose is unavailable until an operation exists. Subgraphs is a reusable-definition shelf, not a primitive operation family. Retain useful legacy node discovery in the same workspace with clear graph-mode filtering.

Match the reference proportions: 110×43px family rows, 46px pitch, 20px outline icons, 8px leading inset and 9px icon gap. Family flyouts are about 155px wide, leaf flyouts 250px, rows 32px. The first flyout aligns with its opening family row; the second aligns with its own subfamily row. Clamp/flip each menu to the pane without overlapping its parent. Use an aligned icon/title/shortcut grid, opaque charcoal surfaces, colored uppercase subfamily labels and quiet trailing shortcodes. Use original or established product outline icons with similar visual weight; do not reproduce Gaea's icon artwork.

Right-click genuine empty canvas opens searchable node creation at that point. Node > Add/search and graph-local Tab provide equivalents without intercepting normal form navigation. Search covers titles, aliases, purpose, shortcodes and saved subgraph names. Context sensitive defaults on, persists, and uses the shared operation/port catalog for direction, artifact kind, phase and capability checks. An empty graph offers complete pre-reply planning and post-reply cleanup examples.

## Nodes, pins, wires and camera

Normal native cards have an icon/title and left inputs/right outputs; height follows the larger actual port-row count. Sources and host terminals expose only real endpoints; terminal Host result is a preview action, not an output pin. Compact cards keep icons and separate real pins, with the alias beneath. Canonical type names remain in details. F2, context menu and an Alias field rename plain-text aliases (maximum 80 characters) without changing identities. Alias, compact state and native node movement are presentation-only; legacy positional prompt order retains its existing semantic consequences.

The entire body, including labels, drags a node after an 8-screen-pixel threshold. Only the pin target initiates a connection. Pin hover affects the dot and connected cables, without a boxed port-row hover background. Pointer cancellation rolls back unfinished gestures. Retain selection and deliberate click-to-preview after dragging.

Ports and cables use artifact kind colors with visible/accessibility labels. One output can fan out; existing primitive inputs have cardinality one. Dragging either input or output shows a live cable from the actual pin. Compatible pin drop connects immediately; occupied input replacement commits only after full validation. Invalid direction/type/phase/self/cycle drops preserve existing connections and explain the reason. Empty-space release retains the pending cable and opens anchored search. Compatible selection creates and connects at the captured graph point in one undo step; ambiguous matching ports require explicit choice. Context sensitive off may create an incompatible node unconnected, preserving validation. Escape, lost capture, pointer cancellation, body/outside drop, chooser dismissal and view changes clear the pending gesture.

Click cables to select, Shift/Ctrl to extend selection, Delete/Backspace to disconnect outside editable controls. Use thin visible paths and wider transparent hit targets. Alt-click a cable disconnects it; Alt-click a pin disconnects all attached ordinary/portal bindings. Rapid Alt-double-click must not delete a neighboring edge or create a reroute. Pin context menus offer individual/all disconnection and navigation. Ctrl-drag a connected input moves its binding to a compatible input; Ctrl-drag an output moves all consumers to another compatible output atomically. Preserve originals on rejection/cancellation; empty-space Ctrl-move cancels. Plain wire double-click inserts a compact typed Reroute at the exact point. A Reroute is a deterministic passthrough and makes zero model requests.

These new typed connection/rewire/reroute gestures apply to native schema-3 graphs. Preserve legacy merge/append/prepend/activate/result/together/save/loop meanings, keyed Decider/State endpoints, group-member wiring and legacy wire double-click cycling. The shared renderer can present both graph modes, but dispatches their distinct validated editing semantics. Migration enables the new native behavior without turning legacy links into artifact edges.

Middle-mouse drag pans and the wheel zooms around the pointer. Preserve the optimized Canvas camera range and transform-only scheduling already shipped rather than adopting the prototype's narrower arbitrary range. Nodes and wires share one coordinate transform; drag displacement, pin endpoints, connection drafts, hit targets, contextual creation and reroutes use the same graph/screen conversions. Menus and gesture thresholds remain in screen coordinates. Cameras are finite, bounded and independent per graph view. Valid MMB initiation establishes keyboard ownership so real Escape cancels panning from a fresh workbench. No new focusable divs or hidden sidebar bounds.

## Typed graph composition

Introduce native graph schema 3/runtime 2 for named source/destination ports, portal records and subgraph instances. Explicitly migrate schema-2 primitive edges to stable `out`/`in` endpoints while preserving node IDs, legacy message-order semantics and existing saved-data readers. Existing `lattice-workflow` and `comfytavern-workflow` package kinds remain readable. New exports use `lattice-workflow`; new standalone subgraph files use `lattice-subgraph`. Preserve host aliases, storage namespaces and old guidance cleanup already shipped.

Native schema-2 workflows retain workflow envelope schema 1/minRuntime 1. Composed schema-3 workflows use envelope schema 2/minRuntime 2. Standalone subgraphs use envelope schema 1/minRuntime 2. Exact supported pairs are validated; unsupported native versions fail visibly instead of falling through to legacy execution. New envelope sizes are capped at 2,000,000 UTF-8 bytes. Preserve the older envelope's existing 2,000,000-character reader bound and plain-data protections for compatibility; multibyte fixtures exercise both policies.

One shared catalog defines port IDs, labels, kinds, cardinality and operation settings. Use it for validation, execution, geometry, search, portal selection and subgraph interfaces. An output artifact is addressed by root workflow ID, full stable instance-ID path, node ID and port ID; display names never bind dependencies. Represent paths structurally or with an unambiguous encoding so separator-containing IDs cannot collide.

Import into graph is distinct from Open workflow. Parse/sanitize before mutation, prepare a complete candidate, remap node/wire/group/component/portal/instance identities and every internal reference, and namespace imported model roles. Preserve internal wiring and relative placement without auto-connecting equal names. Show phase, unresolved local model roles, terminal effects and computed request bound before one undoable insertion. Reject native/legacy or pre/post mismatch with an Open separately alternative. Import never activates, runs, publishes or applies. Repeat imports allocate fresh IDs; failure leaves the destination intact. History must include roles and bundled definition snapshots.

Legacy additive import preserves its existing single Output invariant. A fragment without a second Output can be inserted; importing a second legacy Output rejects with actionable Open separately or export-a-fragment guidance. Do not silently remove, reconnect or import an inert extra Output. Native multiple-terminal workflows retain their reviewed execution behavior.

Prepared changes capture both the semantic signature and complete editable-document signature. A later body/alias/control/topology edit requires repreparation or preservation through a validated patch; a reviewed insertion must not overwrite intervening presentation changes. Camera/selection changes remain outside document preconditions and are preserved at commit.

A portal aliases one existing output with a stable ID, name and artifact kind. Input-side Connect to portal and node Manage portals/P offer compatible selection, rename, source/consumer navigation and restore-visible-wire. Resolve portals to ordinary edges before cycle/cardinality/type checks and execution. Hidden dependencies remain visible as named input references. Scope portals to their containing graph/instance; crossing a subgraph boundary requires an exposed interface port. Rename is presentation-only; endpoint changes invalidate affected recordings.

A subgraph contains Subgraph Input/Output boundary nodes and configurable stable typed interface ports. Each interface entry maps to exactly one matching boundary; reject duplicate/missing mappings. Root-only Scene Context, Reply Snapshot, Guidance and Apply Reply stay outside reusable bodies. Required primitive inputs cannot become optional merely by marking a wrapper port optional. Exposed parameters map to known typed operation settings; model bindings follow existing role/per-node inheritance.

Instances pin exact definition ID, version and semantic hash in workflow-owned snapshots, plus local parameter/model overrides. Shelf deletion cannot break placed instances. Library edits create explicit revisions; Update instance reviews interface/binding changes, and Make local copy enables private body edits. Read-only pinned/library bodies reject raw drag/connect/delete/clipboard/editor mutations, not just disabled Svelte buttons. Convert selection proposes boundary mappings, deduplicates shared inputs/outputs and commits once; Unpack remaps an editable body and reconnects parent edges, preserving effective overrides.

Manage subgraphs supports create from selection, edit/revise, duplicate, rename, import/export JSON, insert and delete. Portable standalone files bundle nested pinned definitions and recursively strip credentials, provider endpoints, local profile IDs, recordings and chats. Model identifiers/roles remain inspectable for local setup. New package size is at most 2,000,000 UTF-8 bytes; expanded graphs at most 1,000 nodes and 2,000 wires; nesting depth at most 8; direct/indirect definition recursion is rejected before expansion. Bound traversal of wrappers and boundary nodes as well as executable nodes. No runtime file/network resolution.

Expand portals and nested instances into one namespaced DAG, validate before dispatch and execute through the existing primitive executor. Share one root request cap, cancellation signal, binding preflight and host authority; do not recursively call whole-workflow runners. Shared dependencies execute once, independent instances separately. Signatures include semantic definition/port/parameter/binding content and exclude presentation metadata.

## Tabs and root lifecycle

Graph 1 is the permanent main tab. Double-click/Open graph on a subgraph opens its full instance path; reopening focuses the existing tab. Repeated definitions in different instances have independent cameras, node presentation, selection and inspector state. Close hides a view, preserves data and supports reopen. Rename updates tab labels/breadcrumbs; deletion reconciles descendant tabs to a surviving parent. Main view has no redundant header; child/library views have breadcrumbs and scope/version labels. Provide accessible tab overflow and Close active/others/reopen commands.

Separate root workflow identity/run epoch from active editor view identity/epoch. Internal view changes cancel only unfinished gestures and obsolete editor continuations, not the root run or its accepted completion. Opening a different workflow retains the existing cancellation/freshness policy. Root Run/Stop, assignment, enabled state, provenance and reviewed Apply always use the root workflow. Keep library inspection visibly separate from instance editing.

## Execution feedback and previews

Add observer-safe, ordered run events and a pure reducer projection. Plan publication identifies unique executable primitive units, dependencies and qualified addresses. Events include run ID, increasing sequence, timestamps and safe provenance, with node/request phase and settlement events. Observer errors cannot fail execution; duplicate/out-of-order/obsolete events and late completions after cancellation are ignored. Cache setup/binding diagnostics outside camera/selection/tab projections so presentation paths perform zero host/domain/model work.

Graph state, bottom-left meter, run details and selected-node diagnostics consume that projection. Running gets a bright orange ring; Failed gets red and a dim readable interior; descendants are Blocked and unrelated omitted work is Not run. Waiting, Queued, Completed, Cancelling/Cancelled, Invalid and Stale remain distinguishable with labels/icons. Processing never steals selection, pin, camera or keyboard focus. Use truthful durations/subphases, request attempts/bounds and reported usage; unknown cost/token values remain unknown. Preserve fail-fast sequential scheduling and existing abort/epoch checks.

The meter uses 4px pixels, 2px gaps, three rows and at most 12 columns, filled downward then right. One accessible button opens hierarchical run details. Top-level nodes/subgraph wrappers are meter rows; counters count expanded primitives without double-counting wrappers/boundaries. With more than 36 rows, the last pixel aggregates remaining rows; details retain every row. Jump actions navigate explicitly to active/failed stages.

Retain one bounded diagnostic run recording with frozen input/output artifacts, errors and captured source/effective-binding provenance. Bound artifact retention separately from the authoritative reviewed candidate, and exclude recordings from portable JSON. Selection follows its node unless pinned; pins use full qualified addresses and remain across tabs. Source deletion labels the preserved recording unavailable/stale instead of rebinding it. Previews support messages/text/structured findings/patches and original/candidate comparison according to actual artifact type. All terminal outputs remain inspectable.

The diagnostic recording has a 4,194,304-byte total UTF-8 serialized budget, a 262,144-byte per-artifact budget and a 65,536-byte rendered-text limit. Deduplicate immutable artifact references. Reserve metadata before payloads and retain payloads in stable plan order; truncate strings at safe character boundaries and retain non-parseable structured prefixes only as explicitly labeled text. When payload space is exhausted, keep a visible omitted marker plus qualified address, kind, state, timestamps and safe error/request summary. Bound metadata labels/error text; test the complete recording against the total cap with 1,000-node and oversized-artifact fixtures. Keep the full authoritative terminal candidate outside this diagnostic budget, unchanged by truncation; preview text never supplies Apply authority.

Run to here is explicit target-rooted planning: structural validation remains whole-graph, but dependencies, required bindings, reachability and request bounds follow the target's upstream closure. Run each dependency once, omit unrelated/downstream work, show the bound before dispatch, and never publish Guidance or grant intermediate Apply authority. Only the existing fresh reviewed terminal path applies a reply. Semantic graph/source/binding changes invalidate/cancel; presentation changes preserve recordings. No automatic paid rebuild/retry.

Global structural checks include malformed endpoints, type/direction/cardinality conflicts, hidden cycles and invalid/recursive definitions. Required connections, enabled dependencies and model bindings are execution-completeness checks scoped to the selected upstream closure. Targeted runs permit absent root Guidance/Apply terminals and unrelated unfinished branches; a global structural cycle still rejects them. Full root runs retain terminal requirements. Preview targets identify an actual operation/output or terminal host result and must resolve unambiguously.
